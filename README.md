# 定期契約・経過勘定管理（contract-ledger）

ビル等の定期契約をマスタ管理し、月次の費用計上仕訳・支払仕訳を生成して、
**前払費用・未払費用・未払金などの経過勘定残高を月単位で管理**するWebアプリです。

- 入力部署：**総務経理部**／**管理部**（ビルメンテナンス）
- バックエンド：Supabase 既存プロジェクト **fixed-asset-ledger**（テーブルは `ct_` 接頭辞で追加。既存テーブルには触れません）
- フロントエンド：Vite + React + TypeScript（静的サイトとして配信）
- 元データ：Excel「01.定期契約マスタ」

## 画面と機能

| 画面 | 内容 | 総務経理部 | 管理部 |
|---|---|:-:|:-:|
| ダッシュボード | 契約数・月額換算・要設定・更新/解約通知期限のアラート | ○ | ○ |
| 契約一覧 / 新規登録 / 契約詳細 | 検索・絞込・CSV出力、契約の登録・編集、按分（ビル/ホテル）、内訳、**枝番による改定と変更履歴** | ○（本社含む全件） | ○（本社契約は非表示） |
| 物件別一覧 | 物件ごとの月額・年額合計（全ビルトータル）、按分反映、科目・区分で絞込 | ○ | ○ |
| 月次計上 | 当月の計上額の計算（Excel「02_月次費用」と同じ判定）、従量・手入力契約の実績入力 | ○＋仕訳生成・締め | ○（実績入力） |
| 仕訳・CSV出力 | 生成された仕訳の確認、調整仕訳、会計ソフト取込用CSV（シート「仕訳CSV」の28列、Shift_JIS） | ○ | — |
| 経過勘定残高 | 科目×月の月末残高、契約別内訳、開始残高の自動計算・登録 | ○ | — |
| マスタ | 物件・取引先・勘定科目・税区分（会計ソフトのコード対応）・選択肢・設定 | ○ | 閲覧（取引先は追加可） |
| ユーザー権限 | Supabaseのユーザーに部署・権限を割当（管理者のみ） | 管理者 | — |

権限：**管理者**＝全操作＋ユーザー管理・締め解除／**編集**＝入力・更新／**閲覧**＝見るだけ。
権限はすべてデータベースの行レベルセキュリティ（RLS）で強制しています。

## 会計処理の考え方

**契約ID＋枝番**：契約ID＝物件コード×100000＋連番（Excelと同じ）。金額・条件の変更は「改定（新しい枝番）」で
新しい適用開始日を指定し、旧枝番は前日付で解約済になります。月次計上は期間で自動的に切り替わります。
すべての登録・変更・削除は変更前後の値ごと履歴に残ります。

**月次計上（ct_calc_month）**：Excel「02_月次費用」の判定を再現しています。

- 月次×月額 → 月額をそのまま計上
- 年次×年額（または一括） → 年額÷12（切捨て）を毎月計上し、**年払対象開始月**に端数を調整
- 半年×年額（または一括） → 契約金額を**半年分**として÷6 を毎月計上し、対象開始月とその6か月後に端数を調整
- 従量・手入力 → その月の実績（税抜）を入力した契約のみ計上
- 月次契約で支払区分が未設定・不明なものは、計上はしますが「支払区分未設定（支払仕訳が作られません）」を確認事項に出します
- 消費税は契約の消費税額（未入力なら税抜×税率の切捨て）

**仕訳生成（ct_generate_month）**：経過勘定は**税込**で管理します。

| | 借方 | 貸方 |
|---|---|---|
| 費用計上 | 損益科目（税抜）＋消費税（外税） | 相手科目＝経過勘定（税込） |
| 支払（月次） | 経過勘定（税込） | 預金 1120 |
| 支払（年払い） | 経過勘定（年額税込） | 預金 1120 |

支払仕訳の時期は「当月分 支払月」で決まります（当月払い＝当月、翌月払い/翌月末＝翌月、翌々月払い＝2か月後、
前月払い＝前月に翌月分を支払）。年次契約は「年払い 支払月」に年額を、半年契約は支払月とその6か月後に半年分を支払います。
例：年払いの前払費用は支払月に計上され、毎月の費用計上で取り崩されます。
支払仕訳が不要な場合は、マスタ → 設定 `auto_payment` を `false` にしてください（その場合は会計ソフト側の支払仕訳と残高を突き合わせます）。

**按分**：契約に按分行（物件＋金額）を設定すると、計上仕訳を金額比で物件（＝部門コード）ごとに分けます。端数は最大の行で調整。

**締め**：月を締めると、その月の仕訳・実績は変更できません（解除は管理者のみ）。CSV出力済みの仕訳は「作り直し」でも残ります。

**開始残高**：運用開始月の月初時点の経過勘定残高。「経過勘定残高 → 開始残高 → 自動計算」で、
契約の支払ルールから推定値（未払いの過去月分、前払いの未償却残など）を作れます。会計ソフトの残高と突き合わせて調整してください。

## セットアップ

### 1. データベース（Supabase：fixed-asset-ledger）

`supabase/migrations/` の SQL をファイル名の順に適用します（SQL Editor に貼り付けて実行、または Supabase CLI で `supabase db push`）。
既存テーブルは変更しません。

### 2. 初期データ（Excelからの取込）

Windows（Python・Excel 不要）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\import_excel.ps1 -Path "01.定期契約マスタ.xlsx"
```

Python がある環境：

```bash
python3 -m pip install openpyxl
python3 scripts/import_excel.py "01.定期契約マスタ.xlsx" > supabase/seed/seed_data.sql
```

どちらも `supabase/seed/seed_data.sql` を作ります（取込ルールは同じ）。投入前に次のコマンドで、
マイグレーション＋テスト＋初期データがローカルの PostgreSQL（PGlite）で通ることを確認できます。

```bash
npm run test:db -- --seed supabase/seed/seed_data.sql
```

生成された SQL を SQL Editor で実行します。物件・勘定科目（科目登録リスト）・選択肢・取引先・契約を投入します（再実行しても重複しません）。
取込時の整理：

- 同じ契約IDで「ビル＋ホテル（物件コード200番台）」の行 → 1契約＋按分行に統合（2700001・4200001・4200002）
- それ以外の契約IDの重複 → 次の番号で再採番（2000006・2200002・2400002・5100002・5100003）、備考2に旧IDを記録
- 契約IDと物件コードが一致しない行（160004 → 1600004）も再採番
- 本社（物件コード1）の契約は総務経理部のみ閲覧

> `supabase/seed/*.sql` には取引先・金額などの実データが入るため `.gitignore` で除外しています。

### 3. 最初の管理者を登録

Supabase の Authentication でユーザーを作成（または既存ユーザーを利用）し、SQL Editor で：

```sql
insert into public.ct_profiles (user_id, display_name, department, role)
select id, '（表示名）', '総務経理部', 'admin' from auth.users where email = '（管理者のメールアドレス）';
```

以降のユーザーは、アプリの「ユーザー権限」画面で部署・権限を割り当てます。

### 4. 会計ソフトのコード設定

「マスタ → 税区分」で会計ソフト（コクヨ形式）の **消費税コード・消費税率区分** を、
「マスタ → 設定」で **仕訳入力形式・外税同時入力区分・日付書式・文字コード** を、実際の取込仕様に合わせて設定してください。
仕訳CSVの部門コードには物件コード、取引先コードには契約の取引先コードを出力します。

### 5. フロントエンド

```bash
cp .env.example .env   # VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY を設定
npm install
npm run dev            # http://localhost:5173
npm run build          # dist/ を静的ホスティングへ
```

配信先は Vercel / Netlify / Cloudflare Pages / GitHub Pages など静的ホスティングで動きます（ハッシュルーティング）。
`.github/workflows/deploy-pages.yml` を使う場合は、リポジトリの Settings → Secrets に
`VITE_SUPABASE_URL` と `VITE_SUPABASE_ANON_KEY` を登録し、Pages のソースを GitHub Actions にしてください
（Privateリポジトリで Pages を使うには GitHub の有料プランが必要です）。

## 構成

```
supabase/migrations/   テーブル・RLS・関数（計上計算・仕訳生成・残高集計・開始残高推定）
supabase/tests/        検証SQL（CI は PostgreSQL、ローカルは npm run test:db で PGlite）
scripts/import_excel.ps1 Excel → 初期データSQL（Windows 用、Python 不要）
scripts/import_excel.py  Excel → 初期データSQL（Python 版）
scripts/test-db.mjs    PGlite でマイグレーション・テスト・初期データを検証
src/pages/             各画面
src/lib/csv.ts         仕訳CSV（28列・Shift_JIS）
```

## 主なDBオブジェクト

| オブジェクト | 内容 |
|---|---|
| `ct_contracts` / `ct_contracts_v` | 契約（契約ID×枝番）／一覧用ビュー（物件名・科目名・月額換算・計上対象判定） |
| `ct_contract_allocations` / `ct_contract_items` | 按分／内訳 |
| `ct_contract_history` | 変更履歴（トリガーで自動記録） |
| `ct_monthly_actuals` | 従量・手入力契約の月次実績 |
| `ct_journal_entries` / `ct_opening_balances` / `ct_periods` | 仕訳／開始残高／月次締め |
| `ct_calc_month(月)` | 月次計上額の計算 |
| `ct_generate_month(月)` | 計上・支払仕訳の生成 |
| `ct_accrual_balances(開始月, 終了月)` | 経過勘定の月次残高（契約×科目×月） |
| `ct_suggest_opening(月)` / `ct_apply_suggested_opening(月)` | 開始残高の推定・登録 |
| `ct_create_revision(契約, 開始日)` | 改定（新しい枝番） |
